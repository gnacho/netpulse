v2.54.0▾

NetPulse 2.54.0

This release is about what the screen was not telling you. Four features make the panel explain more, and a batch of fixes make it stop lying in the places where it was.

Icons that name the device

Searching the icon picker by the word Fridge and the row taking the new icon

Sixty smart-home icons in ten categories, searchable by their name in your language. A fridge stops looking like a generic box, and the search finds it by typing what it is. The catalog came from @Bann-DEV in #2107, and #2113 is the test that keeps it honest when someone adds a tile.

What each device asks for

DNS activity for one device with the 1 hour and 24 hour windows

Per-device DNS activity from the AdGuard query log: the domains a client resolves, how often, and which ones were blocked, in a one hour or one day window. It sits in the device detail, next to the client that asked. #2081 built it, and #2119 made it show something, because it was reading with a lower case MAC while the log was stored in upper case.

Quiet is not offline

A neighbour entry in STALE coming back to REACHABLE and the host staying online

A wired host with a static address that goes quiet used to drop off the map. Now the unit pings its stale neighbour and re-reads the table, so the address and the MAC are confirmed and an idle host stays online. #2108 added the recheck, #2109 extended it to IPv6 over NDP, and #2110 sweeps the subnets a unit routes to find hosts that never left an entry at all. The report behind it is #2063.

Chinese and Russian

The same panel in English, Spanish, Chinese and Russian, with dates following each language

The whole interface in Chinese and in Russian, catalogs complete and reviewed. Dates and numbers follow each language too, not only the labels. Chinese came in #2070, from @Bann-DEV, and Russian in #2083, from @sers88.

Also in this release

  • What's new page. The app now explains each release with animated cards, in all four languages. #2116 added it, and the dot on the version stamp stays until you open it.
  • Traffic per client. The device detail shows down, up and total over 1 hour, 24 hours, 30 days and 12 months, with the series for the same window. @tombacchetta asked for it in #2076 and the panel answers with the per-client history the server already had.
  • Wi-Fi clients with no IP are marked as such, and leave one info entry in the activity log after two minutes instead of looking broken. #2111 closed the request @crowedavid opened in #1984.
  • Docker. An optional server image with the UI and the agents inside, published to GHCR on every tag for amd64 and arm64. @sers88 wrote it in #2101 and the pipeline in #2105.
  • A smaller agent. Built without encoding/json/v2: 7.8 MB down to 7.4 MB on amd64, which is 5.8% less. #2096 measured it before and after.
  • The client table rebalances its columns and uses a single line in the 2xl tier, from #2106.
  • A quieter panel. The SNMP community field says it is read-only (#2080), the unit column is translated (#2098), the splash background follows the theme (#2099) and the landing page counts demo clicks (#2093).

Fixed

  • The per-device DNS panel showed nothing until #2119 fixed the case mismatch between what ingest stored and what the request asked for.
  • Responses from handlers that wait on a unit died at the 15 second write timeout, so a reinstall that worked still showed a red "server unreachable" line. #2112 gave each handler its own ceiling, and it came from the install report in #1894.
  • The rack offers cables between fleet units again, from the FDB of the designated unit. The interface and the implementation had drifted apart, and #2120 put them back together.
  • MACs are normalised with one parser at the boundaries in #2121, which was losing GL clients with hyphenated addresses and breaking the ?mac= filters. #2134 closes the same hole on ingest, for any pusher that sends lower case or hyphenated addresses.
  • Discovery no longer marks an authorised host as "Key missing" when its board has no model field, the case @xvlvx0 described in #2122.
  • A chain of nested device hubs draws every level, each device once, and its cable is emitted once. #2123 and #2124 are the two halves of the same bug, reported by @spskeldon.
  • A bridge unit only names the peer on a port when its FDB makes it unambiguous, which is what @crowedavid asked for in #1976 after a port insisted it was connected to the wrong switch.
  • owut stops aborting because -r is repeated when the exclusion list is already in UCI, tracked in #2102.
  • A polled switch is no longer drawn twice in the topology, from #2104.
  • BATMAN-adv LOOP DETECT frames stop showing up as clients and stop holding topology nodes. @tam481 explained them in #1818 and @crowedavid confirmed they were mesh probes, not hosts.
  • Data tables hidden for screen readers no longer stretch the page scroll area, from #2103.

v2.51.4▾

Units that will never run the agent are now first class. A router with very little flash, or one where the package simply does not fit, used to be a second-class unit: it showed up in the fleet, but its inventory was a guess, its config backup was only possible by hand and the weekly schedule ignored it entirely. This release gives it an inventory mode of its own, the config backup over SSH from the fleet list, and the same backup on schedule. In parallel, the agent that does fit small devices now ships compressed, so fewer units end up in that situation at all.

The other half of the release is about honesty in the UI. An install that took longer than a browser timeout was reported as a network failure with the reason thrown away one layer below, and a unit under plain SSH produced connection noise that no log line on the server could explain. Both are now visible for what they are.

Testing this against real hardware turned up three defects that no unit test had caught. The config backup over SSH relied on base64, which the stock OpenWrt image does not ship, so the backup failed on exactly the units it was written for. The networks view was empty on every unit, because the probe discarded the line that says what kind of section each one is. And a partial router update reset the gateway flag, so switching a unit to SSH inventory quietly dropped it from the gateway role.

Added
  • Each unit declares its inventory mode: auto, agent or SSH (#1917).
  • Each unit reports where its inventory came from and how old it is (#1917).
Fixed
  • An agent install keeps its output, on success and on failure (#1894).
  • A slow install is no longer reported as a network failure (#1894).
  • The configuration backup is offered in the fleet agent list on units that only answer over SSH (#1899).
  • The scheduled config backup covers units that only answer over SSH (#1924).
  • The config backup over SSH works on units without base64 in the image (#1935).
  • The networks view lists the interfaces of a live unit, with the agent or over SSH (#1936).
  • A partial update of a router no longer resets its gateway flag or its agent-only flag (#1937).
  • The OpenWrt package ships a compressed agent (#1891).
  • Every SSH probe that does not go through the connection pool leaves a line in the server log (#1893).
  • A release reuses the agent binaries when the agent did not change (#1916).
  • The networks card renders on a live server (#1918).

v2.51.3▾

Agent self-upgrade works again. The previous release packed the agent binaries with UPX, and the startup guard that checks the embedded agent version scanned the raw bytes for a version string that compression had hidden. The server therefore started with agent upgrades disabled, so every fix that travels inside the agent was unreachable. The build now writes a small version stamp next to the binaries and the server reads it first, keeping the byte scan as a fallback for unpacked builds. Nothing else changes.

Fixed
  • Agent self-upgrade works again on servers built after the binaries were packed with UPX (#1914). The #1246 guard scanned the embedded bytes for the version string, and compression hides it, so every release since the packing change started with self-upgrade disabled and logged a mismatch that did not exist. The build now writes the agent version in a stamp file next to the binaries and the server reads that stamp first, keeping the byte scan for hand-copied or unpacked sets.
v2.51.2▾

Your network, the way you configured it. Every client now carries the VLAN its bridge actually learned, and the router page lists your OpenWrt networks with their members, their subnets and their traffic, instead of only a chassis with jacks. The agents are a third of their former size, so an upgrade fits in a small flash again, and an agent with no init script restarts itself instead of waiting for a reboot nobody knew was needed. Plus a batch of fixes from the people who run this daily: backups that clean up after themselves and work over plain SSH, a firmware target that stays where you picked it, charts that stop inventing slopes, and a topology that finds the unmanaged switch behind your managed one.

If you run the packaged agent, this release also ships agent 3.0.37. It is required for per-client VLANs, the access point interface and the restart without an init script: a unit that keeps agent 3.0.36 will not show those fixes. On Merlin-style installs without procd the first update still needs one manual restart, and every later one replaces its own process.

Added

  • The router page can now be read as the networks the unit declares, not only as a chassis with jacks (#1889). A networks card lists each OpenWrt network with its device, its subnet, its VLAN, its member ports, how many clients sit on it and the traffic of its device. Both ways of segmenting a box go through the same code: a bridge with VLAN filtering, where the network device is br_switch.999 and the members come from its bridge-vlan section, and one bridge per network fed by a tagged subinterface, where br-iot learns its VLAN from eth0.999. Traffic is the counter of the network device rather than a sum of its ports, a unit without per-interface counters shows no figure instead of an invented one, and clients are counted only when their VLAN is known. Reading the configuration also fixed a quiet parsing bug: a UCI list written as 'eth1 lan1 lan2' was being treated as one single port name.
  • A configuration backup no longer needs an agent on the unit (#1899). The button only rendered for a unit with an agent, so a router managed over plain SSH had no way to keep a copy of its config even though the server can already reach it. The server now builds the archive itself with sysupgrade --create-backup, brings it back base64 encoded over the SSH channel, always removes the temporary file on the unit, whose /tmp is RAM, and stores it where the agent backups already live, so one list and one download serve both kinds. A unit that does have an agent still prefers the event stream and only falls back to SSH when the agent is not connected.
  • Reinstalling an agent now shows what the install script actually said (#1894). The handler discarded the script output with _, so the operator got a red "exit status 1" that vanished after eight seconds and the server journal had nothing at all. The output is captured and returned with the response, on failure and on success, it is written to the server journal either way, and the UI shows it in a collapsible frame under the message. A failed reinstall no longer hides itself: the error stays until the next attempt, so it can be read, copied and attached to a report.
  • The SSH pool writes what it does to the system log (#1893). A unit showed bursts of "Exit before auth" in dropbear and there was nothing on the server side to correlate them with: no host, no reason, no rhythm. Every new connection is now logged with its host and user, every discarded connection is logged before the redial that follows, and every dial failure is logged with the real cause, whether that is a host key problem, an authentication rejection, a timeout or a network error, together with the consecutive failure count and the backoff. Failures are rate limited to the first and every tenth so a dead unit cannot fill the journal, and a recovery line closes the episode.

Fixed

  • An unmanaged switch behind a managed one is inferred again (#1791). The inference required a managed distribution node whose MAC matched the bridge address of the switch exactly, and it only accepted units of type managed-switch. An SNMP switch usually announces an LLDP chassis MAC that is not its bridge address, and a unit declared as external with SNMP did not pass the type check at all, so the leaf switch never appeared and its clients stayed in the fan-out of the managed switch. Every managed unit with a forwarding table is walked now, and when no node matches its MAC the leaf hangs from the fleet unit itself, keeping the physical port on each client. Access points with an agent are still excluded, because their multi-MAC port is their uplink.
  • Wired clients fan away from their unit instead of always to the west (#1791). The fixed arc sent every chip towards the gateway when the unit sat on the right edge, on top of the links between units. The arc is now centred on the direction from the gateway to the unit, so a unit on the right fans its clients to the right and a unit on the left keeps the layout it had.
  • Traffic charts no longer invent a ramp between two buckets (#1901). A point in these series means "the highest rate seen inside this bucket", so a straight segment to the next point claims the link spent the whole gap climbing, and a one minute burst inside an hour renders as a triangle that spans the neighbouring hours. The WAN chart, the fleet sparkline and the aggregated port ranges now draw steps, which say exactly what was measured and no more. The 24h port chart keeps its straight segments because it reads raw instantaneous samples, and the latency chart is untouched since it is not a max-per-bucket series. One detail differs from the report: every WAN range is bucketed, including 1h, whose points are three minute maxima, so the step applies there too instead of only to the hourly view.
  • Discovery no longer offers a unit that is already in the fleet (#1895). A candidate was marked as already added only when its IP was byte-identical to the host string in the configuration, so a unit added by DNS name, by a name with different case or a trailing dot, or by an IP with a port showed up with an Add button while the gateway, added by plain IP, was the only one recognised. The comparison now normalises case, port and the trailing dot, resolves configured names to their addresses, and also matches the reverse DNS name of the candidate, with name resolution bounded so a stale name cannot slow the scan down.
  • A config backup no longer stays on the unit after it is uploaded (#1897). Every manual or scheduled backup wrote its tarball under /tmp and left it there, and on a router /tmp is RAM, so each snapshot took memory away until the next reboot. The agent now deletes the local file once the operation ends, whether the upload succeeded or not, since the copy that matters is the one the server keeps with retention. The firmware flow keeps its local backup on purpose: that one is reported in the result so it can be recovered by hand when sysupgrade fails.
  • The target version chosen on a firmware card stays where it was left (#1898). The selection lived only in the local state of the page, so a refresh, leaving and coming back, or the ten second auto-refresh that runs while an upgrade is in flight put the dropdown back to whatever the server had stored, and nothing was saved unless the separate Save button was pressed. Choosing a version now saves it, a reload no longer overwrites an edit that is still local, and scheduling a recurrence saves the target shown in the dialog before saving the schedule. That last case mattered beyond the dropdown: a scheduled run flashes the target stored on the server, and a unit with none had its recurrence disabled when it fired, with "no firmware target saved" as the only explanation.
  • A client is tagged with the VLAN its bridge actually sees (#1757). The forwarding table was read from one bridge only and every port carrying a dot was thrown away, so a router that segments with 802.1Q subinterfaces, where the real ports are eth0.777 and eth0.999, lost its wired clients altogether: no port, no VLAN and no line in the topology. Every bridge the unit has is read now, a subinterface counts as a port, and each MAC carries the VLAN the bridge learned it on, which is the only evidence of where a client lives. A forwarding table without that field leaves the client without a VLAN instead of guessing one from the default of the port.
  • A wireless client keeps the interface and the SSID that served it (#1757). The hostapd path built each station without either, so on any OpenWrt that answers over ubus every WiFi client arrived with an empty interface, and the topology, which resolves the VLAN of a station through its AP interface, had nothing to colour. The interface is taken from the object that was queried and the SSID from iw dev, and the VLAN of an AP interface now carries the name and the subnet of the network it serves.
  • An upgrade that swaps the binary but cannot restart says so instead of leaving the unit lying (#1900). On a host without a procd script there is nothing to ask for a restart, so the new binary stayed on disk, the old one kept running from memory, and the UI reported the unit as up to date until the next reboot. That covers the Merlin-style installs under /jffs, Synology and any manual or Entware deployment, which are exactly the units that ended up as external in 2.49.x. The agent now replaces its own process with the binary it just installed, keeping the PID, the arguments and the environment, which starts the new build in place and leaves the OpenWrt path untouched. If even that fails, it reports the failure with the reason while it is still alive. The availability flag now uses the same criterion as upgrade all, a live agent stream rather than the row type, so the badge and the command stop disagreeing. And a restart that never completes stops sitting at restarting: after ninety seconds the row shows a terminal failure that names the cause and lives longer than the ordinary progress state, so an operator sees it instead of an empty slot.
  • A guest without a tag is no longer painted with a VLAN it does not have (#1757). When Proxmox declares no tag=, the guest sits in the native VLAN of the bridge of the host, not in the VLAN of the port where the host is plugged. Inheriting the VLAN of the host chip marked those guests with an unrelated network, so a container on an untagged bridge showed up in the VLAN of a segmented one.

Changed

  • The link out of an alert reads View unit instead of View router (#1896), which is the wording the rest of the interface already settled on. The device list link was renamed with it, and the Spanish strings say Ver unidad.
  • An agent ships compressed, so a router with little room can install it (#1890). The update downloads the new build to /tmp and moves it over the installed one, which means a unit needs twice the size of the agent free before it even starts: 15 MB for a 7.5 MB agent, on a flash of 16 MB. The report came from a unit with 10 MB where the upgrade could not begin. Every architecture is now packed with UPX in --best --lzma, which takes the five binaries from 6.9-8.3 MB down to 2.0-2.4 MB, and the cost is about 170 ms at start-up on x86. The build refuses to produce agents without UPX instead of skipping the step in silence, a test fails when an embedded agent is not packed, and the release checks the mark and the size before publishing. The embedded sha256 is computed over the packed bytes, so integrity checks are unchanged.

v2.51.0▾

NetPulse v2.51.0

Two months of work since v2.50.0: 86 pull requests, 88 commits and 58 documented changes, most of them reported by people running NetPulse on their own hardware. This release is as much theirs as ours.

If you run the packaged agent, this release also ships agent 3.0.35 and the server embeds it, so a reinstall, a self-heal or a package download from the UI brings every unit up to date.

The short version

  • Backups are now useful off the machine they came from. A nightly backup is a single .tar.gz with the database, the .ssh directory and tls/, taken from a consistent snapshot. Restoring on a fresh host brings back data, the SSH key the server uses to reach the routers, and the certificates.
  • A reinstall can no longer leave an agent down, silent or downgraded. The installer says which step failed, keeps the service running until it has something to install, finishes the setup even when a step fails, and refuses to replace an agent that is newer than the binary the server carries.
  • Agents come back in seconds after a server restart. The SSE reconnect delay used to grow to five minutes on every restart because an unclean cut counted as a failure.
  • Short-lived addresses are no longer clients. A MAC that comes and goes within a minute never reaches the device table, the counters or the "new client" alert.
  • The channel plan stops suggesting moves that change nothing, and when a radio refuses to scan it now says why instead of showing an empty table.
  • Less disk, for longer. Five-minute buckets are kept for 90 days instead of a year, and the copy the updater takes before an update is compressed, which takes a 419 MB database down to about 130 MB per copy.

Upgrading from v2.50.0

These are the behaviour changes worth knowing before you upgrade. Everything else is additive.

| Change | What to expect |

|---|---|

| Backup format | New backups are netpulse-<timestamp>.tar.gz instead of .db.gz. Restore with tar -xzf netpulse-<timestamp>.tar.gz inside the data directory. Existing .db.gz and .db files are still purged by the retention policy, they just are not produced anymore. |

| Backup contents | The archive holds credentials: netpulse.db, .ssh/ and tls/. Treat it like a secret. |

| Five-minute retention | client_bw_5m and port_series_5m now keep 90 days instead of 365. Raw samples stay at 7 days, daily rollups are kept forever. The first purge after the upgrade will delete 5m rows older than 90 days. |

| Update copies | deploy/update.sh compresses the pre-update database copy. Rollback restores from the .gz and drops stale -wal/-shm files first. |

| Agent downgrade guard | The binary, package and reinstall endpoints return 409 agent_downgrade_refused when the unit reports a newer agent than the one embedded in the server. Add ?force=1 to override. A unit with no reported state is never blocked, so a dead agent can still heal itself. |

| New client dwell time | A MAC unknown to the server must be seen for at least 60 seconds before it counts as a client or fires an alert. The waiting window lives in memory and starts over when the server restarts. |

| Per-unit push interval | The agent cadence is a per-router setting (agent_interval, 0 = the agent default of 30 seconds). It is written to the UCI config on routers that carry the package. |

Added

  • The ASU exclusion list can be written on the router from the firmware card. When owut check reports packages missing in the target version, the card offers to append them to attendedsysupgrade.owut.remove, so the next build keeps them.
  • The exclusion list is read from the router itself. owut check also reads the list the owner already maintains, instead of only the one NetPulse wrote.
  • The server can serve the OpenWrt agent as an installable package. It builds the .ipk on the fly from the embedded binary and serves it from /api/agents/{slug}/package, so a reinstall goes through opkg/apk and lands in a conffile that survives a sysupgrade.
  • The agent push interval is a per-unit setting. A busy access point wants a short cadence, a modem on a metered link does not.
  • A radio with no neighbour scan now says why. The agent keeps the last line of iw's stderr and sends one outcome per radio with the interface it ended up using and the number of BSSes it saw. The channel plan shows it under the radio.
  • The firmware card can reset the upgrade state of a router. An attempt stuck in running or rebooting for more than fifteen minutes no longer needs an API call to clear.
  • Clients in the topology show their VLAN, wired and wireless. The router list carries the bridge VLAN filtering table and each chip is coloured by the VLAN of the port it sits on.
  • Configuration backups can run on a schedule. A card on the Firmware upgrades page picks a weekday and a time, and the server keeps the last and next run so a restart does not lose the schedule.
  • Pending upgrades show their configuration backup. The upgrade card exposes the archive that belongs to the unit, so restoring after a flash no longer means hunting for a file by date.
  • New firmware alerts. NetPulse now raises an alert when a new firmware version is available for a device, with the target version in the detail.

Changed

  • An automatic backup is a single .tar.gz holding the database, the .ssh directory and tls/. It used to carry only netpulse.db, so restoring on a fresh host brought back data and configuration but the server could not reach a single router until the key was recreated by hand.
  • Five-minute buckets are kept for 90 days instead of a year, and the pre-update copy is compressed. On a live install the database had reached 419 MB, 182 MB of it in 5m buckets built in 64 days, and an uncompressed copy per update did not fit the disk.
  • Every page shares the same width and the same header gap. Alerts and Settings capped their content at their own width while the rest used the shell, so the pages looked like different products.
  • Every page header uses the layout of the topology page. Breadcrumb in small caption with a chevron, one-line explanation below, actions on the right. This touched Home, Alerts, Devices, Settings, Channels, Reports, Firmware upgrades and Help.
  • The page title is no longer printed twice. The top bar already shows it, so the copy under the breadcrumb is gone.
  • The per-unit actions live together. Regenerate token moved from Settings > Fleet to the Actions column of the agents card, and Forget host key moved from the unit detail to the same place.
  • The in-app help covers integrations and certificates. Two flows are new: the add-ons group in Settings and the vendor catalog, and the certificate and plain HTTP options.
  • The rack picker names its groups the way the rest of the UI does, and the rack editor grew a set of long-requested fixes:
  • a unit can be mounted at full width, half width or a third of the rack, so two or three devices fit on the same shelf;
  • a rack is created with any height from 1 to 45 U instead of six presets;
  • ports of a racked unit show their name instead of the SNMP ifIndex;
  • patch panel ports are numbered 1 to 48 instead of the internal p01 key;
  • the picker favours the unit name over its model, and lists every wired client that can be racked;
  • the front panel only shows physical ports, not the VLAN interface or the LAG.

Fixed

Backups and retention
  • An automatic backup no longer fails with archive/tar: write too long on a live server. The archive sized the database entry from a stat and then copied until EOF, so a database that grew between the two calls wrote more bytes than the header declared. It now takes a VACUUM INTO snapshot first and copies exactly the declared size.
  • The nightly backup no longer leaves the SSH key and TLS material out.
  • Update copies are compressed and the rollback restores from the compressed file.
  • Five-minute buckets stop eating the disk (90 days instead of a year).
Agent, installer and self-heal
  • A reinstall that fails no longer leaves the agent down. The installer stopped the service before it had anything to install, so a download that could not reach the server or a binary whose checksum did not match left the unit stopped with the old binary in place.
  • A reinstall that cannot finish its setup says so and still brings the agent back. After the binary swap, any failing step of the remaining setup aborted the script with the service still stopped. Environment file and init script are now written to a temporary file and moved, and the restart is always attempted, with a distinct exit code when the agent does not come up.
  • A reinstall that cannot download the agent binary or install the package now says so on stderr, instead of dying silently on the first failing command.
  • An SSH reinstall that fails reports the last line the router printed on stderr, not just Process exited with status 1, so the reason (a failing curl, a full filesystem, a missing command) reaches the operator.
  • The init written by the installer no longer registers a service whose binary is missing. After a sysupgrade, when the self-heal could not fetch the agent, procd was told to run a path that did not exist and the unit stayed dead until someone looked.
  • A reinstall no longer downgrades an agent that is ahead of the server.
  • An agent whose SSE stream is cut by a server restart reconnects in seconds instead of minutes.
  • Rotating the agent token now reaches the configuration the agent actually reads. The packaged init prefers the UCI config and only falls back to the environment file when the UCI one is empty, so the rotation used to leave the old token in the file that mattered.
  • The served installer is always LF. A checkout with core.autocrlf=true put CRLF in the embedded script and busybox refused to parse it.
  • The packaged OpenWrt agent now receives its UCI configuration. The procd service passes server, token, slug, interval, scan interval, ping targets and SPKI fingerprint in a single call.
Clients and devices
  • Addresses that come and go within a minute are no longer clients. Randomised MACs, phones that probe once and mesh units that bounce an association all reached the device table, the counters and the "new client" alert.
  • Locally administered MACs are recognised by the server itself, not only by the agent discovery scan, so a MAC that lives in the switch FDB is flagged too.
  • A locally administered MAC with no address and no lease is no longer remembered.
  • Units report the MACs of all their interfaces. Only the bridge MAC was absorbed, so the CPU port of a DSA switch, a VLAN interface or a radio could be learned by a neighbour and appear as an unknown client.
  • The default route of the gateway no longer appears as a client.
Channels and topology
  • The neighbour scan survives a radio whose AP interface refuses to scan. On Asuswrt and other Broadcom firmwares the AP interface answers -95 while the managed one works. The agent now retries on another interface of the same radio, at most twice, and reports the outcome.
  • The channel plan stops moving a wide radio to the other half of the channel it already uses. The current block was matched by equality, so a 40 or 80 MHz radio on a non-primary channel matched nothing, scored zero and got a suggestion that was the same block.
  • Opening the Channels page no longer starts a WiFi scan with the periodic scan off.
  • Topology links end on the client node, clients behind an inferred leaf switch hang from it, and right-edge chips fan to the right instead of piling over the incoming links.
Monitoring and SNMP
  • A managed Netgear switch reports its chip again, reading model, chip and firmware from the FastPath enterprise subtree.
  • TP-Link switches report model, firmware, CPU and memory through their enterprise MIB, since the firmware answers neither ENTITY-MIB nor HOST-RESOURCES-MIB.
  • SNMP switches read the generic ENTITY-MIB, so a monitored switch shows its firmware and a sensible model name.
  • MikroTik temperature comes from the health table, with CPU and RAM from HOST-RESOURCES.
Firmware and owut
  • An owut upgrade that finishes updates the stored firmware target, so a unit upgraded through the flow stops showing the old version.
  • The owut flow is two steps. install runs without an image and the download gate cannot drop third-party packages.
  • The firmware target dropdown defaults to the latest version and lists what ASU would build, instead of a stale owut versions list.
  • An owut install no longer marks a successful flash as failed when the router reboots.
UI and settings
  • A gateway without AdGuard no longer leaves half a row empty. The row width was decided by the visibility checkboxes while the card decided on its own whether to render.
  • The pre-flight checks speak the language of the UI. Their detail text was written by the server in Spanish, so an English interface showed 3393 MB libres next to a translated label.
  • A resolved alert shows what it resolved, instead of a bare internal id.
  • The settings group goes back to its Integrations label, and the section that hosts the vendor integrations manager is the one called Complementos (Add-ons in English).

v2.50.0▾

Router integrations are here. This release completes the Integrations section that deploys, runs, updates and edits vendor pushers for you: MikroTik RouterOS, Asuswrt and Asuswrt-Merlin (installed on the router itself over SSH, the Merlin way under /jffs or with a password sign-in on stock dropbear), UniFi controllers, and a vendor catalog that grows without touching the core. The integration code lives in a separate repository, netpulse-integrations, and each vendor ships as its own standalone binary speaking the same signed ingest contract as the native agent. You only ever download and run the code for hardware you actually own: no UniFi controller, no UniFi code on your box. That is the deal that makes NetPulse compatible with more platforms every release while the server binary carries no vendor code inside and the shared code stays a small contract anyone can review.

Added

  • UniFi controller vendor (#1695): a read-only unifi-pusher for self-hosted UniFi Network controllers, both UniFi OS consoles (UDM, UDM Pro, UNVR and similar) and classic standalone ones; ui.com cloud accounts are not supported, the pusher only speaks to a controller reachable on the LAN. One site per integration: gateways, switches and access points with their ports and uplinks (the topology hangs together without LLDP), wired and wireless clients with band and signal, MAC-to-IP mapping, and gateway uptime and identity. Surfaces with no verified read-only match (DHCP leases, per-interface counters, VLANs, roaming, CPU, temperature) are not emitted. It deploys from the Integrations section like RouterOS, on the host that runs the server.
  • The Integrations vendor catalog ships as a manifest (#1706): vendors_seed.json names each vendor with its release tag prefix, binary and architectures, so adding a vendor or an architecture is a manifest entry instead of a compiled table in the core.
  • Integrations in ssh mode accept password authentication (#1708): when the optional companion file <data-dir>/integrations/<slug>.sshpass (0600, same discipline as the environment file) exists, the server signs in to the router with the integration username and password; without it the server key stays the default and preferred path. The create and edit forms reuse the same password field for it (empty on edit keeps the current one), the password never reaches the database or any API response, deleting the integration removes the file, and an authentication rejection reports its own ssh_auth_failed code instead of the generic ssh_failed. Stock Asuswrt (dropbear with password auth only) now works with no manual key setup.
  • Inactive agents in the fleet table now offer Rearm, Reinstall and the copyable install command next to Remove, so a rejected token (HTTP 401 after a reboot or a server move) can be fixed without removing the agent or losing its history. NetGrip rows offer Rearm only and external pushers keep Remove only.
  • The card and the detail of a unit pushed by an integration (RouterOS and other vendors) show why it is offline: authentication rejected, missing API endpoint (old firmware, REST needs RouterOS 7+), connection refused or pusher stopped, with the raw pusher error on the tooltip.
  • The on-box server init script now refuses to start when its data dir is not a real mount (default overlay paths excluded), so an unmounted USB stick can no longer leave a fresh SQLite database on flash. It also moves to START=99 to let USB mounts settle first.
  • The agents table marks a rejected-token agent with its own badge the moment the pusher authenticates with a stale token (a reboot or a server move does it), and the badge clears itself on the first valid push. The Integrations rows carry the same offline classification as the unit detail, so a dead integration explains itself in place (#1719).

Changed

  • The manual documents the agent recovery flow (Rearm restarts the agent service, Reinstall rotates a rejected token) and the agent tooltips and banners point to the agents section on Devices, which hosts the reinstall action, instead of the router detail page.

Fixed

  • Integrations in ssh mode on procd vendors (#1709): the generated init now loads the router environment file into the pusher process with a single procd_set_param env call (extra calls overwrite each other, so only the last variable survived), refuses to start when the environment file is missing or unreadable, and keeps the file watcher so an env change still restarts the service with the new values. Before, a procd vendor started its pusher with no NETPULSE_* or vendor variables at all.
  • Heavy write volume on-box (#1700): the on-box server now runs SQLite in WAL mode with synchronous=NORMAL and temp_store=MEMORY, the same engine as every other deployment. The previous on-box choice (rollback journal DELETE + synchronous FULL, Fase 9 R6) rewrote pages and journal on every transaction and tripled the measured write volume (45 GB/day on a USB stick with a 107 MB database, versus 13.7 GB/day in WAL with the same fleet). WAL with synchronous=NORMAL cannot corrupt on a power cut; only the commits not yet synced are rolled back. The hourly checkpoint and nightly jobs now run for on-box installs too, so the -wal file stays bounded.
  • SQLite aggregation spills (the etilqs_* temp files) no longer hit disk by default. The report measured two ~3.16 MB temp files per 60 s window, about 9.1 GB/day and two thirds of the server's process writes with a ~100 MB database; with temp_store=MEMORY the same aggregation happens in RAM (a few MB per query).
  • Asuswrt over SSH installs the Merlin way (#1705): binary and environment under /jffs/netpulse, a small pidfile control script for start, stop and status, and the boot hook as a managed block inside /jffs/scripts/services-start (removed cleanly on uninstall) instead of a procd service, which Asuswrt does not have. Nothing is written outside /jffs except the hook line.
  • Enabled local integrations resume on boot (#1704): after a server restart every enabled pusher starts again, and rows left stale by a crash or a kill reconcile to what is actually running.
  • Pre-pin pusher environments heal on update and edit (#1699): an integration created before the SPKI pin change gets its environment rewritten by the next update or edit instead of staying pinned-less until it is deleted and recreated.
  • Pusher environments ship the server SPKI pin (#1685): external pushers verify the server TLS certificate against the pinned public key, the same trust model as the native agent.
  • The greeting line on the Overview ("N important alerts") now counts the same alerts as the bell and the Alerts page (unread, level-filtered), instead of the health score breakdown. A health penalty without a visible alert, such as a down VPN peer with the vpn category set to "Nada", used to leave a phantom counter that could not be cleared from anywhere (#1707).
  • OpenWrt 21.02 on-box package (GL.iNet GL-MT6000 report): the .ipk now installs /etc/init.d/netpulse, the agent init and the uci-defaults scripts as executable (0755), and the packaging scripts verify the modes inside the built .ipk.
  • OpenWrt 21.02 on-box package: the procd init now uses ONE procd_set_param env call with all variables (in 21.02 each extra call overwrote the previous one, so NETPULSE_ONBOX and DATA_DIR never reached the process), and stdout/stderr are set as boolean params so server logs show up in logread.
  • Gateway autodetection no longer picks the ISP-side (public or CGNAT) address on an on-box server: when the default route's via is not a private LAN address, the gateway is the router itself and its LAN IP is taken from the private subnet route. Dedicated LAN servers keep the previous behavior.
  • The server generates its SSH keypair in-process (crypto/ed25519 + x/crypto/ssh) instead of calling ssh-keygen: on OpenWrt 21.02 the available keygen is Dropbear's and writes a format crypto/ssh cannot parse, which silently degraded the server to the demo dataset. An existing unparseable key is backed up and regenerated, and the public key fingerprint is computed in-process.
  • The default on-box port is now 3100 instead of 3000, which collides with the AdGuard Home UI shipped by GL.iNet firmware. Existing installs keep their configured port.
  • The initial bootstrap password is removed from UCI after a password change, so the generated plaintext no longer stays in /etc/config/netpulse forever.
  • README: DEMO_MODE=1 requires AUTH_PASS even in demo mode, and the settings section holding the SSH public key is called Fleet (formerly documented as Network).
  • NETPULSE_DB_ROLLBACK_JOURNAL=1 restores the previous on-box SQLite journal engine (DELETE + synchronous FULL) after the #1700 default change; NETPULSE_DB_TEMP_STORE (memory | file | default) controls where SQLite aggregation spills go, and is also settable on-box via the new db_rollback_journal / db_temp_store UCI options.

Security

  • Dependencies: minimatch forced to 11.0.3 through overrides (#1721, Dependabot alert 37). The globparts amplification advisory has no 10.x patch and the package only reaches the build through the lint toolchain, so the override is the only path.
  • Dependencies: pick up the gonzalop/mq audit fixes (#1693).

v2.47.0▾

The portability release, shaped by Bann-DEV's fleet

The agent now works past OpenWrt, and almost everything here exists because Bann-DEV ran NetPulse on an ASUS GT-BE98 Pro (Asuswrt) and a Synology NAS and measured every gap.

The agent goes portable. Without ubus it still reports uptime, RAM (from /proc/meminfo, with the server computing used and percent from the same bytes), timezone (IANA, from /etc/localtime), wireless clients via iw station dump, LLDP neighbours in plain text when the JSON build is missing, CPU temperature via hwmon when a box has no thermal zones, and the WAN port resolved from the default route (LLDP-verified bridge member first). Plus a proper asuswrt router type with the AP role, agent-driven upgrades and no SSH probing. (#1481, #1491, #1498, #1500, #1501)

CPU temperature that means CPU. On x86 the agent reads the package sensor (x86_pkg_temp, coretemp) instead of the first thermal zone, which was usually the ACPI ambient reading. Boxes without zones fall back to hwmon. (#1484)

The agent survives sysupgrades. Both the one-liner installer and the server-side reinstall now pin the binary, env, init script and rc.d symlinks in /etc/sysupgrade.conf — the self-heal needs its entry point to come back. (#1476)

Topology: your bridge ONT, drawn. ARP learned on the gateway's WAN port counts as the WAN peer, so a bridge-mode ONT behind PPPoE appears under Internet instead of vanishing; fleet units without a bridge MAC can be pinned by router id; managed switches stop listing their own CPU MAC as a client; and LLDP links read the uplink speed from the child end when the parent does not report it. (#1485, #1489, #1471)

Presence timeline on Reports. Per-client online spans with a searchable picker, 7/30 day range, online time, span count and connections in 24h — with the open span carried into the window, so always-on hosts no longer plot as empty. (#1493)

Forget SSH host key from the UI. After a reflash or an upgrade that regenerates the keys, clear the pinned key from the unit detail and let the next poll re-register it with trust on first use. (#1477)

Also: a modem/ONT device type (#1495), the releases refresher backs off and surfaces failed checks (#1478), the runtime uplink beats a stale board.json WAN label (#1482), resolved alerts carry their own title and timestamp (#1466), standalone config backup from the unit card (#1462), and both READMEs credit the people behind the project (#1499).

And thanks to sweetlazyboy (#1493), crowedavid (the WireGuard, firmware and topology threads) and pl-komuch (#1475); juflo's BBox integration (#1474) is on the way.

The WireGuard release, shaped by David's fleet

Almost everything in this batch exists because crowedavid runs NetPulse against a real, picky fleet and writes down what he sees.

Peers that matter, alerts that tell the truth. Mark a WireGuard peer as *urgent* and its drops notify like a unit's; the rest just land in the log. Down peers stay visible on the map (dashed ring, card with handshake data), urgent peers get slot priority, and the health score finally cares about VPN state: a dead interface or urgent peers down no longer leave the score at 100, with every penalty explained in the breakdown. (#1441, #1440, #1442)

Connect events you can trust. Tunnels initiated by the local unit no longer lose their connect alert, every reconnection emits its own event (no more 5-minute coalescing hiding the second drop), and the tracker follows the stable public key instead of a dump index that drifted between polls. (#1443, #1445)

Firmware targets that exist. A daily check (configurable) against the official OpenWrt releases index gates the outdated alert: it only fires when the configured target is actually published. A made-up target raises its own configuration warning instead of a permanent alert, and the Firmware page shows the check state with a "check now" button. (#1444)

Topology, tighter. Wired clients behind managed switches are claimed by their switch's FDB instead of dangling off the gateway (#1417); FDB-resolved unit links get their speed from the child end's port table when the parent reports none (#1429); GL.iNet WireGuard peers show their real names and VPN curves anchor cleanly into the Internet node (#1433); Proxmox hosts with zero guests draw as hypervisors (#1446); and the agent (3.0.19) finds LAN bridges that are not br-lan/br0, fixing "0 clients" switches (#1435).

Alerts with a lifecycle. Weak-signal alerts resolve themselves once the client stabilizes above threshold + hysteresis for N consecutive samples (both configurable), keeping duration and recovery value; and clearing or reading alerts updates the overview and badge instantly over SSE instead of waiting for the next poll cycle. (#1452, #1434)

Also: roaming and 802.11r views work on agent-only fleets (#1431, #1450), the NetGrip-embedded units get a proper "Update NetGrip" action (#1436), the landing page is TypeScript now (#1425), and the method selector UI got its review pass: grouped owut steps with tooltips, no leftover Save button, and an expected-SHA256 field for local uploads. v2.45.0▾

Firmware upgrades, your way

Every unit now picks how it updates: owut (ASU), an image URL, or a local upload of an image you built elsewhere (the server stores it, computes the sha256 and flashes it verified). The owut flow gains explicit steps - *check* to review what would change, *download* to build and fetch the image to the router without flashing, *install* to flash the downloaded one - while the classic "Upgrade now" stays for those who want it in one go. And the config backup no longer dies in the router's /tmp: the agent (3.0.18) uploads it to the server before flashing, the last five per unit are kept, and you can download them right from the unit's card. (#1414)

Alert levels are notification policy now

Setting a category to "Urgent only" used to make everything else vanish from the log. From this release everything is always recorded in the log and the feed; the level only decides what notifies - use the feed's category filters to hide things visually. On top of that, the firmware alert becomes one episode per unit instead of re-firing every 5 minutes, version strings are compared as versions, and a target older than the installed release gets its own possible-downgrade alert. (#1413, #1411, #1412)

Also in this release
  • Per-subscriber push language: each push subscription remembers your UI language and the notification is composed in it; subscriptions are user-owned, so unsubscribing only removes your own. (#1334)
  • Agent matching with physical criteria: when identical bridged APs share a hostname, the bridge MAC decides; an ambiguous hostname no longer invents an association. (#1334)
  • Topology renders all switch-classified routers, not just the first three, and edge units fan their clients toward the center of the canvas. (#1422, #1416)
  • SSID impostor: your own fleet no longer reports itself - units whose agent doesn't report own BSSIDs are recognized by their fleet MAC and derived radios. (#1402)
  • Firmware manual brought up to date with the actual page. (#1415)

What's Changed

Agent versioning decoupled from the server release (#790). Until now every server release rebuilt the agent with the release tag number, so the whole fleet was flagged as outdated on every release even when the agent code had not changed at all. The agent now has its own version, stored in agent/VERSION (starting at 3.0.0), which CI injects into both the agent binary and the server. The fleet updates once to 3.0.0 and from then on only gets an update prompt when the agent code actually changes; the release workflow fails if the agent code changed without a version bump. Updating from older versions jumps straight to this release - database migrations are state-based and idempotent, no step-by-step path needed.

The rearm button is no longer offered for external agents (#792). The router detail header showed "Rearm" for any stale agent, including external pushers without SSH (e.g. a beacon-managed switch), which the backend already rejected. The button now hides itself for external kinds everywhere.

Qué hay de nuevo

Versionado del agente desacoplado del server (#790). Hasta ahora, cada release del server rebuildaba el agente con el número del tag y toda la flota se marcaba como desactualizada en cada release aunque el código del agente no hubiera cambiado. El agente pasa a tener versión propia en agent/VERSION (arranca en 3.0.0), que el CI inyecta tanto en el binario del agente como en el server. La flota se actualiza una vez a 3.0.0 y, a partir de ahí, solo recibe aviso de actualización cuando el agente cambia de verdad; además, la release falla si el código del agente cambió sin subir la versión. Actualizar desde versiones anteriores salta directo a esta release: las migraciones de la base de datos son por estado e idempotentes, sin pasos intermedios.

El botón «Rearmar» ya no se ofrece en agentes externos (#792). La cabecera del detalle de un router mostraba el rearme para cualquier agente caído, incluidos los externos sin SSH (p. ej. un switch gestionado por beacon), que el backend ya rechazaba. The recorded key type is whatever the router's dropbear presents (ssh-rsa in our OpenWrt fleet); NetPulse does not force RSA.
