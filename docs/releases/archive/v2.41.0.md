## Fleet topology you can trust

A v2.40.0 regression chained fleet units in a loop and left the gateway without links. Fixed: Omada port annotations can no longer act as neighbor identity for uplink resolution (they keep labeling ports), any residual LLDP cycle between units degrades to device/FDB evidence, and semantic link labels now sit on the link midpoint instead of piling up in the corner.

## More device icons - additively

Air conditioners, boilers/heating and single-board computers (orange/nano/banana/rock pi) now classify to their own types with dedicated icons (AirVent, Heater, CircuitBoard). Strictly additive: tokens already claimed by an older rule stay put, so no existing device changes its type or icon. Clients also keep their name and icon when a DHCP lease expires, and a MAC is never shown as a hostname anymore.

## Also in this release

- Local agent URL behind a reverse proxy: `NETPULSE_AGENT_URL` overrides the public URL in the agent install line, reinstall, re-emit and auto-reinstall (#1335, #1336)
- borky's contributions integrated with credit (#1332, #1333): DHCP reservations end-to-end, mDNS host records, finer vendor matching, embedded agent 3.0.15
- Tablet rail: the portrait rail footer now has the expand toggle and the collapsed state works from md up (#1318)
- Expanded detail: the Edit button anchors to the top-right, aligned with the first detail row (#1341)
- New classified device types: clima, caldera, placa (#1340) - requested in discussion #1337

**Versión 2.41.0**

**Topología de flota fiable.** Corregida la regresión de v2.40.0 que conectaba las unidades de flota en bucle y dejaba al gateway sin enlaces: las anotaciones de puerto de los Omada ya no identifican vecinos para los uplinks (siguen etiquetando), cualquier ciclo residual degrada a evidencia sólida y las labels de enlaces se colocan en su sitio.
