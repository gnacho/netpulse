## What's Changed

### Added

- **WAN / VLANs / alerts series from the borky fork (#946)** - multi-WAN support, uplink policy in the agent, alert when the internet exit connection changes, router detail shows its connections, VLANs read from the router, port panel linked by the real port. Attributed.
- **Per-device SNMP polling health (#930)** - ok/fail counters per SNMP router, unprivileged ICMP ping fallback, snmp-failing alert after 3 consecutive failures only when the host answers ping (hint at a wrong community or port), recovery alert, counters in the router detail and the ports card.
- **Last seen for clients (#954)** - a new device_seen table tracks the first and last time each MAC was seen online (all sources, not only wireless). The device detail shows both and the clients table gains sortable columns on xl+ widths. The server sends epochs and the app formats the relative time with the active locale.

### Fixed

- **SNMP switches showed no clients despite a populated FDB (#928)** - two chained causes, confirmed with the reporter's snmpwalk: (1) the Q-BRIDGE fallback only ran when the dot1d walk returned zero raw PDUs, so data that did not parse never gave qbridge a chance (#948); (2) TP-Link Omada switches (SG3428X-M2, SG3210X-M2) index the dot1d table by <vlan>.<mac> (7 octets) instead of the plain MAC from RFC 1493, and the parser required exactly 6, dropping every entry (#950). The FDB log line now also shows raw PDU counts per walk.
- **"First seen" was never populated outside the demo (#954)**.
- **Auto-generated slugs invisible in the UI (#951)** - log lines now lead with the device name (slug in parentheses), and the device detail info card shows an ID row.

### Notes

- Agent 3.0.5: the WAN/VLANs series touches the agent (uplink policy); everything else is server and web.
- The clients table column visibility selector (third suggestion from #954) is a follow-up in #958.
- Thanks to @crowedavid for the detailed #928 report, the TP-Link Omada testing and the #954 suggestions, and to borky for the WAN/VLANs series.

## Novedades

### Añadido

- **Serie WAN / VLANs / alertas del fork borky (#946)**: soporte multi-WAN, política de uplink en el agente, alerta cuando cambia la conexión de salida a internet, el detalle del router muestra sus conexiones, VLANs leídas del router y panel de bocas enlazado por el puerto real. Atribuido.
- **Salud del sondeo SNMP por dispositivo (#930)**: contadores de aciertos/fallos por router SNMP, ping ICMP de respaldo sin privilegios, alerta snmp-failing tras 3 fallos seguidos solo si el host responde a ping (pista de community o puerto mal configurados), alerta de recuperación y contadores en el detalle del router y en la tarjeta de puertos.
- **Last seen en clientes (#954)**: la nueva tabla device_seen registra la primera y la última vez que el server vio online a cada MAC (todas las fuentes, no solo wireless). El detalle del dispositivo muestra ambas y la tabla de clientes gana columnas ordenables en pantallas xl+. El server manda epochs y la app formatea el relativo con el locale activo.

### Corregido

- **Switches SNMP sin clientes pese a tener el FDB poblado (#928)**: dos causas encadenadas, confirmadas con el snmpwalk del reporter. (1) El fallback a Q-BRIDGE solo se probaba cuando el walk dot1d devolvía cero PDUs crudos; datos no utilizables nunca daban opción a qbridge (#948). (2) Los TP-Link Omada (SG3428X-M2, SG3210X-M2) indexan la tabla dot1d por <vlan>.<mac> (7 octetos) en vez de la MAC desnuda de RFC 1493, y el parser exigía exactamente 6: descartaba todas las entradas (#950). La línea de log del FDB muestra además los PDUs crudos de cada walk.
- **"First seen" nunca se poblaba fuera del demo (#954)**.
- **Slugs autogenerados invisibles en la UI (#951)**: las líneas de log usan ahora el nombre del dispositivo (slug entre paréntesis) y la tarjeta de información del detalle muestra la fila ID.

### Notas

- Agente 3.0.5: la serie WAN/VLANs toca el agente (política de uplink); el resto son cambios de servidor y web.
- El selector de columnas visibles de la tabla de clientes (tercera sugerencia de #954) queda como follow-up en #958.
- Gracias a @crowedavid por el reporte detallado de #928, las pruebas con sus TP-Link Omada y las sugerencias de #954, y a borky por la serie WAN/VLANs.
