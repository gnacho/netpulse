# v2.28.1

Server-side fix. The agent is unchanged (AGENT_VERSION stays 2.26.11).

**EN**: SSH polling no longer saturates low-end APs (#550). When the server polls a router over SSH (no agent), it still used the pre-#373 command pair: iwinfo assoclist for clients and an iwinfo radio summary on every 5s tick. On a single-core AP (e.g. Archer A7 v5) that spiked load. The SSH path now mirrors the agent fix from #373: clients via ubus hostapd get_clients (authoritative even on an empty AP, no iwinfo fallback per poll), iwinfo only as a single-pass combined fallback, and the radio summary cached for 5 minutes instead of refreshed every poll.

**ES**: El sondeo SSH ya no satura APs de bajas prestaciones (#550). Cuando el servidor sondea un router por SSH (sin agente), seguía usando el par de comandos previo al #373: clientes por iwinfo assoclist y resumen de radios por iwinfo en cada tick de 5 s. En un AP de un solo núcleo (p. ej. Archer A7 v5) eso disparaba la carga. La vía SSH ahora replica el fix del agente (#373): clientes vía ubus hostapd get_clients (autoritativo incluso con un AP vacío), iwinfo solo como fallback combinado en una pasada, y el resumen de radios cacheado 5 minutos en lugar de refrescarse en cada poll.
