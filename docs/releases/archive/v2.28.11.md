# v2.28.11

## English

**Fixed**
- **Agent degraded AP WiFi (#591)**: the agent ran an active `iw dev scan` (which takes the radio off channel) on every full probe, ~every 30-37 s per device (measured in the scan table). On access points this repeatedly disconnects IoT clients and causes signal loss. Passive scans now run at most every 10 minutes, after startup, or immediately when the server requests a refresh over SSE. Embedded agent version bumped to 2.26.12 so the fleet can update. Also fixes a map-order flake in `TestParseUsteer` that broke CI.
- **SSH re-onboard silently accepted changed keys (#603)**: on a known host with a different key, the pool refreshed `known_hosts` in the background (accept-new with refresh), defeating MITM protection. The pool now rejects the connection and marks the router `unreachable`/`hostKeyChanged`; an admin confirms the re-onboard explicitly (new endpoint `POST /api/routers/{id}/accept-host-key` and a button in the router detail), which drops the known_hosts entry and re-runs TOFU on the next poll. The recorded key type is whatever the router's dropbear presents (ssh-rsa in our OpenWrt fleet); NetPulse does not force RSA.

## Español

**Corregido**
- **El agente degradaba el WiFi de los APs (#591)**: lanzaba un `iw dev scan` (scan activo que saca la radio del canal) en cada sondeo completo, cada ~30-37 s por dispositivo (medido en la tabla de scans). En puntos de acceso provoca desconexiones de clientes IoT y pérdida de señal. Ahora se ejecuta como mucho cada 10 minutos, tras el arranque, o de inmediato si el servidor pide un refresh por SSE. La versión de agente embebida sube a 2.26.12 para que la flota se actualice. También corrige un test flaky de orden de mapa en `TestParseUsteer` que rompía el CI.
- **El re-onboard SSH auto-aceptaba claves cambiadas (#603)**: ante una clave distinta en un host conocido, el pool renovaba `known_hosts` en silencio (accept-new con refresh), anulando la protección MITM. Ahora la conexión se rechaza y el router se marca como `unreachable`/`hostKeyChanged`; un admin confirma el re-onboard explícitamente (nuevo endpoint `POST /api/routers/{id}/accept-host-key` y botón en el detalle del router), que borra la entrada de known_hosts y vuelve a hacer TOFU en el siguiente sondeo. El tipo de clave registrado es el que presente el dropbear del router (ssh-rsa en nuestra flota OpenWrt); NetPulse no fuerza RSA.
