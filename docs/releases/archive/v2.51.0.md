# NetPulse v2.51.0

Two months of work since v2.50.0: **86 pull requests, 88 commits and 58 documented changes**, most of them reported by people running NetPulse on their own hardware. This release is as much theirs as ours.

If you run the packaged agent, this release also ships **agent 3.0.35** and the server embeds it, so a reinstall, a self-heal or a package download from the UI brings every unit up to date.

---

## The short version

- **Backups are now useful off the machine they came from.** A nightly backup is a single `.tar.gz` with the database, the `.ssh` directory and `tls/`, taken from a consistent snapshot. Restoring on a fresh host brings back data, the SSH key the server uses to reach the routers, and the certificates.
- **A reinstall can no longer leave an agent down, silent or downgraded.** The installer says which step failed, keeps the service running until it has something to install, finishes the setup even when a step fails, and refuses to replace an agent that is newer than the binary the server carries.
- **Agents come back in seconds after a server restart.** The SSE reconnect delay used to grow to five minutes on every restart because an unclean cut counted as a failure.
- **Short-lived addresses are no longer clients.** A MAC that comes and goes within a minute never reaches the device table, the counters or the "new client" alert.
- **The channel plan stops suggesting moves that change nothing**, and when a radio refuses to scan it now says why instead of showing an empty table.
- **Less disk, for longer.** Five-minute buckets are kept for 90 days instead of a year, and the copy the updater takes before an update is compressed, which takes a 419 MB database down to about 130 MB per copy.

## Upgrading from v2.50.0

These are the behaviour changes worth knowing before you upgrade. Everything else is additive.

| Change | What to expect |
|---|---|
| **Backup format** | New backups are `netpulse-<timestamp>.tar.gz` instead of `.db.gz`. Restore with `tar -xzf netpulse-<timestamp>.tar.gz` inside the data directory. Existing `.db.gz` and `.db` files are still purged by the retention policy, they just are not produced anymore. |
| **Backup contents** | The archive holds credentials: `netpulse.db`, `.ssh/` and `tls/`. Treat it like a secret. |
| **Five-minute retention** | `client_bw_5m` and `port_series_5m` now keep 90 days instead of 365. Raw samples stay at 7 days, daily rollups are kept forever. The first purge after the upgrade will delete 5m rows older than 90 days. |
| **Update copies** | `deploy/update.sh` compresses the pre-update database copy. Rollback restores from the `.gz` and drops stale `-wal`/`-shm` files first. |
| **Agent downgrade guard** | The binary, package and reinstall endpoints return `409 agent_downgrade_refused` when the unit reports a newer agent than the one embedded in the server. Add `?force=1` to override. A unit with no reported state is never blocked, so a dead agent can still heal itself. |
| **New client dwell time** | A MAC unknown to the server must be seen for at least 60 seconds before it counts as a client or fires an alert. The waiting window lives in memory and starts over when the server restarts. |
| **Per-unit push interval** | The agent cadence is a per-router setting (`agent_interval`, 0 = the agent default of 30 seconds). It is written to the UCI config on routers that carry the package. |

## Added

- **The ASU exclusion list can be written on the router from the firmware card.** When `owut check` reports packages missing in the target version, the card offers to append them to `attendedsysupgrade.owut.remove`, so the next build keeps them.
- **The exclusion list is read from the router itself.** `owut check` also reads the list the owner already maintains, instead of only the one NetPulse wrote.
- **The server can serve the OpenWrt agent as an installable package.** It builds the `.ipk` on the fly from the embedded binary and serves it from `/api/agents/{slug}/package`, so a reinstall goes through `opkg`/`apk` and lands in a conffile that survives a sysupgrade.
- **The agent push interval is a per-unit setting.** A busy access point wants a short cadence, a modem on a metered link does not.
- **A radio with no neighbour scan now says why.** The agent keeps the last line of `iw`'s stderr and sends one outcome per radio with the interface it ended up using and the number of BSSes it saw. The channel plan shows it under the radio.
- **The firmware card can reset the upgrade state of a router.** An attempt stuck in `running` or `rebooting` for more than fifteen minutes no longer needs an API call to clear.
- **Clients in the topology show their VLAN, wired and wireless.** The router list carries the bridge VLAN filtering table and each chip is coloured by the VLAN of the port it sits on.
- **Configuration backups can run on a schedule.** A card on the Firmware upgrades page picks a weekday and a time, and the server keeps the last and next run so a restart does not lose the schedule.
- **Pending upgrades show their configuration backup.** The upgrade card exposes the archive that belongs to the unit, so restoring after a flash no longer means hunting for a file by date.
- **New firmware alerts.** NetPulse now raises an alert when a new firmware version is available for a device, with the target version in the detail.

## Changed

- **An automatic backup is a single `.tar.gz` holding the database, the `.ssh` directory and `tls/`.** It used to carry only `netpulse.db`, so restoring on a fresh host brought back data and configuration but the server could not reach a single router until the key was recreated by hand.
- **Five-minute buckets are kept for 90 days instead of a year, and the pre-update copy is compressed.** On a live install the database had reached 419 MB, 182 MB of it in 5m buckets built in 64 days, and an uncompressed copy per update did not fit the disk.
- **Every page shares the same width and the same header gap.** Alerts and Settings capped their content at their own width while the rest used the shell, so the pages looked like different products.
- **Every page header uses the layout of the topology page.** Breadcrumb in small caption with a chevron, one-line explanation below, actions on the right. This touched Home, Alerts, Devices, Settings, Channels, Reports, Firmware upgrades and Help.
- **The page title is no longer printed twice.** The top bar already shows it, so the copy under the breadcrumb is gone.
- **The per-unit actions live together.** Regenerate token moved from Settings > Fleet to the Actions column of the agents card, and Forget host key moved from the unit detail to the same place.
- **The in-app help covers integrations and certificates.** Two flows are new: the add-ons group in Settings and the vendor catalog, and the certificate and plain HTTP options.
- **The rack picker names its groups the way the rest of the UI does**, and the rack editor grew a set of long-requested fixes:
  - a unit can be mounted at full width, half width or a third of the rack, so two or three devices fit on the same shelf;
  - a rack is created with any height from 1 to 45 U instead of six presets;
  - ports of a racked unit show their name instead of the SNMP ifIndex;
  - patch panel ports are numbered 1 to 48 instead of the internal `p01` key;
  - the picker favours the unit name over its model, and lists every wired client that can be racked;
  - the front panel only shows physical ports, not the VLAN interface or the LAG.

## Fixed

### Backups and retention

- **An automatic backup no longer fails with `archive/tar: write too long` on a live server.** The archive sized the database entry from a `stat` and then copied until EOF, so a database that grew between the two calls wrote more bytes than the header declared. It now takes a `VACUUM INTO` snapshot first and copies exactly the declared size.
- **The nightly backup no longer leaves the SSH key and TLS material out.**
- **Update copies are compressed and the rollback restores from the compressed file.**
- **Five-minute buckets stop eating the disk** (90 days instead of a year).

### Agent, installer and self-heal

- **A reinstall that fails no longer leaves the agent down.** The installer stopped the service before it had anything to install, so a download that could not reach the server or a binary whose checksum did not match left the unit stopped with the old binary in place.
- **A reinstall that cannot finish its setup says so and still brings the agent back.** After the binary swap, any failing step of the remaining setup aborted the script with the service still stopped. Environment file and init script are now written to a temporary file and moved, and the restart is always attempted, with a distinct exit code when the agent does not come up.
- **A reinstall that cannot download the agent binary or install the package now says so on stderr**, instead of dying silently on the first failing command.
- **An SSH reinstall that fails reports the last line the router printed on stderr**, not just `Process exited with status 1`, so the reason (a failing curl, a full filesystem, a missing command) reaches the operator.
- **The init written by the installer no longer registers a service whose binary is missing.** After a sysupgrade, when the self-heal could not fetch the agent, procd was told to run a path that did not exist and the unit stayed dead until someone looked.
- **A reinstall no longer downgrades an agent that is ahead of the server.**
- **An agent whose SSE stream is cut by a server restart reconnects in seconds instead of minutes.**
- **Rotating the agent token now reaches the configuration the agent actually reads.** The packaged init prefers the UCI config and only falls back to the environment file when the UCI one is empty, so the rotation used to leave the old token in the file that mattered.
- **The served installer is always LF.** A checkout with `core.autocrlf=true` put CRLF in the embedded script and busybox refused to parse it.
- **The packaged OpenWrt agent now receives its UCI configuration.** The procd service passes server, token, slug, interval, scan interval, ping targets and SPKI fingerprint in a single call.

### Clients and devices

- **Addresses that come and go within a minute are no longer clients.** Randomised MACs, phones that probe once and mesh units that bounce an association all reached the device table, the counters and the "new client" alert.
- **Locally administered MACs are recognised by the server itself**, not only by the agent discovery scan, so a MAC that lives in the switch FDB is flagged too.
- **A locally administered MAC with no address and no lease is no longer remembered.**
- **Units report the MACs of all their interfaces.** Only the bridge MAC was absorbed, so the CPU port of a DSA switch, a VLAN interface or a radio could be learned by a neighbour and appear as an unknown client.
- **The default route of the gateway no longer appears as a client.**

### Channels and topology

- **The neighbour scan survives a radio whose AP interface refuses to scan.** On Asuswrt and other Broadcom firmwares the AP interface answers `-95` while the managed one works. The agent now retries on another interface of the same radio, at most twice, and reports the outcome.
- **The channel plan stops moving a wide radio to the other half of the channel it already uses.** The current block was matched by equality, so a 40 or 80 MHz radio on a non-primary channel matched nothing, scored zero and got a suggestion that was the same block.
- **Opening the Channels page no longer starts a WiFi scan** with the periodic scan off.
- **Topology links end on the client node**, clients behind an inferred leaf switch hang from it, and right-edge chips fan to the right instead of piling over the incoming links.

### Monitoring and SNMP

- **A managed Netgear switch reports its chip again**, reading model, chip and firmware from the FastPath enterprise subtree.
- **TP-Link switches report model, firmware, CPU and memory through their enterprise MIB**, since the firmware answers neither ENTITY-MIB nor HOST-RESOURCES-MIB.
- **SNMP switches read the generic ENTITY-MIB**, so a monitored switch shows its firmware and a sensible model name.
- **MikroTik temperature comes from the health table**, with CPU and RAM from HOST-RESOURCES.

### Firmware and owut

- **An owut upgrade that finishes updates the stored firmware target**, so a unit upgraded through the flow stops showing the old version.
- **The owut flow is two steps.** `install` runs without an image and the download gate cannot drop third-party packages.
- **The firmware target dropdown defaults to the latest version and lists what ASU would build**, instead of a stale `owut versions` list.
- **An owut install no longer marks a successful flash as failed** when the router reboots.

### UI and settings

- **A gateway without AdGuard no longer leaves half a row empty.** The row width was decided by the visibility checkboxes while the card decided on its own whether to render.
- **The pre-flight checks speak the language of the UI.** Their detail text was written by the server in Spanish, so an English interface showed `3393 MB libres` next to a translated label.
- **A resolved alert shows what it resolved**, instead of a bare internal id.
- **The settings group goes back to its Integrations label**, and the section that hosts the vendor integrations manager is the one called Complementos (Add-ons in English).
