## What's new / Novedades

**EN** — The agent now collects LLDP neighbours itself: every full probe cycle it reads `lldpcli` and ships the neighbours (local port, chassis, management address, capabilities, remote port) in its push. Until now LLDP was only collected by the server over SSH, a path that routers with an agent never take, so the topology map could never promote managed switches or identify LLDP-speaking devices on those fleets. The payload contract is explicit: `available:false` when lldpd is not installed (feeds the in-app hint), missing neighbours when the probe fails that round (anti-flicker), and an honest empty list when there is simply nobody to hear. Network note: a conformant 802.1D switch filters LLDP multicast, so neighbours show up between directly cabled equipment or across unmanaged switches.

**ES** — El agente ahora recolecta los vecinos LLDP por sí mismo: en cada ciclo completo de sondeo lee `lldpcli` y los envía en su push (puerto local, chasis, dirección de gestión, capacidades, puerto remoto). Hasta ahora el LLDP solo lo recogía el server por SSH, una vía que los routers con agente nunca usan, así que el mapa de topología no podía promover switches gestionados ni identificar dispositivos que hablan LLDP en esas flotas. El contrato del payload es explícito: `available:false` si lldpd no está instalado (alimenta el hint de la app), vecinos ausentes si la sonda falla esa ronda (anti-parpadeo) y lista vacía honesta cuando no hay nadie que escuchar. Nota de red: un switch conforme 802.1D filtra el multicast LLDP, así que los vecinos aparecen entre equipos directamente cableados o tras switches no gestionados.
