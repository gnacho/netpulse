# NetPulse 2.55.1

Two defects that only show up on a fleet that has been running for a while: an ISP device reachable over IPv6 was being listed as a client of your own network, and the nightly backup could stop permanently because of a file sitting next to the SSH key.

## A CPE on the WAN is not a client of your LAN

2.55.0 fixed this for IPv4 neighbours. On a gateway whose ISP peer is only visible in the NDP table, the confirmed neighbour came back without its interface, so the WAN filter had nothing to match on and the device was published as a wired client. The confirmed neighbour carries its interface now, both from the agent and from the server's own SSH poll (#2203, reported by @arypien in #2200).

## A backup that survives a foreign file

A `.bak` copy of `known_hosts` owned by root inside the data directory made every automatic backup fail with `permission denied`, because the archive opens the whole `.ssh` directory and stopped at the first file the service could not read. The result was no backup at all and one identical journal line per minute, 922 of them in a single day on the instance that found it. The archive is written without that file now and the journal names what stayed out. A failure that persists is logged once and then once an hour, so the retry stays but the noise does not (#2205).

## Also in this release

- The Chinese interface covers the DNS panels and the SNMP hints again, which stayed in English after the DNS activity work (#2204, by @Bann-DEV).
- The OpenWrt package workflow runs once per tag, so two runs no longer race for the same asset names (#2197).
- The changelog page serves the release captures from the site, so the images load again (#2195, #2196).
- Agents move to 3.0.50, which is the version that carries the interface of a confirmed IPv6 neighbour.
